## Findings

### Blocker 1 — 缺少要求的 exact-channel negative fixtures

`_self_test()` 的失败场景直接调用 `_ledger`、`_structure`、`_artifacts`、`_budget`、`_clean`、`_regressions` 等内部函数，只比较捕获到的 `ContractError.code`。这些夹具没有通过 `main` 或 dispatcher 执行并断言失败进程的完整契约：`rc == 1`、stdout 完全为空、stderr 只有且精确等于对应 `RESULT FAIL ...` 行。因此即使负向路径泄漏 stdout、把错误写到错误通道、附带额外 stderr，现有自测仍会通过。

这也使 task report 中“exact stdout/stderr”证据只覆盖红阶段和 self-test 成功路径，不能证明所列六类新增负向边界的 exact-channel 行为。并且 self-test 内若干 `subprocess.run(check=True)` 与文件操作可能抛出 `CalledProcessError`/`OSError`，`main()` 只捕获 `ContractError`；这些异常会产生 traceback，而非受控的唯一失败行。必须增加从公开入口执行的逐类负向夹具，并精确断言 rc/stdout/stderr。

### Important 1 — real-checkout clean gate 的状态矩阵未被负向夹具覆盖，报告表述超出证据

生产检查 `_clean()` 使用真实 checkout 上的 `git status --porcelain=v2 -z --untracked-files=all -- <scope>`，并分别覆盖 `common` 与 owned scope；从可见实现看，它会对 tracked/index/untracked 污染 fail-closed。

但自测只创建了两个 untracked 文件：`common/dirty` 与 owned `work/modes/stray`。没有任何 common/owned 的 tracked 工作区修改或 staged/index 污染夹具，也未分别验证相应失败码及 exact channel。task report 声称覆盖“tracked/untracked common/owned scope”，与 review package 中可见的夹具不一致。应至少补齐 tracked、index、untracked × common、owned 的代表性负向矩阵。

### Important 2 — worktree cleanup 的部分注册失败路径不可验证，也没有 cleanup 故障夹具

当 `git worktree add` 成功后，`_rollback()` 会把 `worktree remove --force` 非零、目录残留或 worktree 注册残留记为 `cleanup_failed`，所以该常规 cleanup failure 不会 PASS。

但若 `git worktree add` 返回非零且已经产生部分 worktree 注册，`added` 仍为 `False`；finally 分支最多删除目录，不查询、清除或验证 worktree 注册。另因 `remove.returncode or worktree.exists() or ...` 使用短路求值，remove 非零或目录残留时不会继续取得另一项清理状态，无法同时验证目录与注册结果。现有所谓 `rollback-leftover` 夹具只是直接在未回滚的主 checkout 上调用 `validate_reverted_paths()`，没有注入真实 `_rollback()` cleanup/remove 失败，也没有断言 cleanup 失败的 exact channel。应加入可控故障注入，并在所有 add/remove 结果下独立核验目录与注册均已清除；无法清除时仍须确定性 FAIL。
